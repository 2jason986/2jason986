# 你好，我是 2jason986

做 LLM Agent 应用开发。关注的重点是把大模型从「能聊」推进到「能干活」：有工具、有证据、有审核、出错能兜底。

## 在做什么

- **多智能体编排**：把复杂任务拆给多个角色，用严格的输出契约约束每个角色的产出，加独立审核环节和修订上限，避免一条提示词走到底。
- **检索增强**：让回复里的每句话都能追溯到知识库条目，减少编造政策和价格。
- **工具调用**：把检索、查询这类动作交给模型自己决定，同时把工具异常收敛成可观测的结果，而不是让流程崩掉。

## 技术栈

## 代表项目

### [multi-agent-orchestrator](https://github.com/2jason986/multi-agent-orchestrator)

一个零运行时依赖的多智能体编排框架，用客服工单作为落地场景。规划、检索、回复、审核四个角色协作，回复必须带引用、必须通过审核才能发出，修订两轮仍不通过就转人工。

- 严格 JSON 输出契约，编排层依据字段做路由，而不是解析自然语言
- 自己实现的 TF-IDF 检索，中文按字二元组切分，clone 下来十秒内能跑
- 确定性 mock 模型让整条链路离线可跑，51 个测试全部不联网
- 每次都留下可读的执行轨迹，Markdown 和 JSON 双格式

## 工作方式

写代码前先想清楚失败路径。一个 agent 系统能不能上线，取决于模型出错时它怎么表现，而不是模型正常时有多流畅。
